# Angular 18 → 20 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `src/Lus.UI` from Angular 18.1 to Angular 20 with the app behaving identically, so that the frontend being ported from ArmyLuz (written against Angular 20 and `@microsoft/signalr` v10) compiles as written.

**Architecture:** Two sequential `ng update` majors — 18→19, then 19→20 — never skipping. Each major is its own commit with a green build and test run behind it. Third-party packages that gate a major are upgraded *within* that major's task, because `ng update` refuses to proceed while a peer dependency is unsatisfied. The legacy `@angular-devkit/build-angular:browser` builder migrates to the esbuild `:application` builder as part of 19→20.

**Tech Stack:** Angular 18.1 → 20.3, TypeScript 5.5 → 5.8, zone.js 0.14 → 0.15, NgRx 18 → 20, Node 24.3 (already installed), Karma/Jasmine.

**Spec:** [`docs/superpowers/specs/2026-08-18-ai-builders-port-design.md`](../specs/2026-08-18-ai-builders-port-design.md) — decision **D8** in §3.7.

## Global Constraints

- **Target is Angular 20, NOT the latest (22.1.2).** D8: the port source (`ArmyLuz.UI`) is on
  `@angular/core ^20.0.0`, `typescript ~5.8.2`, `zone.js ^0.15.1`, `@microsoft/signalr ^10.0.0`.
  Landing on 20 means ported components compile as written. 20→22 is a separate follow-up **after**
  the document builder is green.
- **Never skip a major.** `ng update` supports one major step at a time; 18→20 directly is
  unsupported and silently leaves migrations unrun.
- **Behaviour-frozen.** This plan changes versions, generated migrations, and blocking third-party
  packages. It changes no application logic. Any behaviour change discovered is a separate commit
  with its own justification.
- **.NET is untouched** — Lus is already on SDK 9.0.301 (D7).
- Every task ends on a green `npm run build` **and** `npm test`, and a commit.
- Work in `src/Lus.UI`. All commands below assume that working directory unless stated.

- [ ] **Step 1: Upgrade the blocking third-party packages to their v19 line**

`ng update` will refuse while these pin Angular 18. Do them first, in one install so npm solves the
graph once:

`--legacy-peer-deps` is required here and only here: for the duration of this step NgRx 19 wants
Angular 19 while Angular 18 is still installed. The next step resolves it. Do not leave the flag in
any committed script.


This applies the v19 migrations automatically. Read its output — it lists each migration it ran.

```bash

```

- [ ] **Step 4: Resolve the remaining peer warnings**

```bash
npm ls 2>&1 | grep -i "invalid\|UNMET" || echo "dependency tree is clean"
```

For each package still pinning Angular 18, install its v19-compatible line. Expected candidates:
`@ngx-translate/core`, `@ngx-translate/http-loader`, `@fortawesome/angular-fontawesome`,
`@ng-select/ng-select`, `ngx-material-timepicker`. Install only the ones that actually report a
conflict — an unnecessary major bump is an unnecessary risk.

- [ ] **Step 5: Build and fix compile errors**

```bash

```

Expected v19 friction, and the fix for each:

**Risks and where they are handled:**

| Risk | Handling |

| `ngx-material-timepicker` has no Angular 20 release | Task 3 Step 4 / Task 4 surface it as a peer conflict. **Deliberately not done:** migrating to standalone components, `provideHttpClient`, or the
`@if`/`@for` control-flow syntax. All are behaviour-adjacent and none are required for the port —
`ArmyLuz.UI` is itself still mostly NgModule-based (35 standalone files out of a much larger tree).
