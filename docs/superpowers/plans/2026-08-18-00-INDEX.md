## Order

```
09 e2e-verification (baseline FIRST — pins the app before anything moves)
        │
01 python-agent-bridge ───── 03 document-builder-backend ──┬── 04 frontend
                                                           └── 05 renderers
07 angular-18-to-20 ──── 02 non-blocking-loading ──────────── 04 frontend

08 i18n-expansion — independent except Task 5 (needs plan 01)
06 auth-hardening — independent, can run at any point
```

**09 executes first** — its baseline suite is the regression gate every other plan must keep
green; running any migration before the baseline exists forfeits the ability to attribute a
regression. Plans **01**, **07**, **08** and **06** then have no dependencies on each other and can
proceed in parallel.
**01 → 03** is the critical path; **07 → 02** is the frontend prerequisite chain.

**07 must land before any frontend port work.** Porting Angular-20 components into an Angular-18
app means migrating the same code twice.

## Why plans 03–05 are written after 01 lands

Plan 01's exit criterion answers questions that materially shape 03–05: whether the subprocess
bridge performs acceptably inside Lus's Railway container, what the real Hebrew round-trip looks
like end-to-end, and what `doc.template_reader` actually recovers from the supplied exemplar. Writing
their task-level detail before that evidence exists would be guesswork dressed as a plan.

Plans 02 and 06 are independent of that evidence and can be written at any time.

Plan 04 is additionally blocked on the canvas concepts being specified — the editable-canvas
contract (C3: a human cell edit emits the same patch op an agent emits) sets its whole task list.

## Global constraints (apply to every plan)

Copied verbatim from the spec — every task's requirements implicitly include these.

- **.NET 9** across all backend projects. `global.json` lives in `src/`, not the repo root; keep it
  on SDK 9.x.
- **Angular 18 → 20** frontend (plan 07; target is 20, NOT latest — D8), single repo (`src/Lus.UI` beside the backend projects).
- **MySQL** via `Pomelo.EntityFrameworkCore.MySql` 9.x.
- **Python ≥ 3.11.**
- **CQRS-lite via MediatR** — every operation is a Command/Query + handler. Builders never bypass
  the command layer.
- **Org scoping is per-handler, not EF global filters.** New tenant-owned reads must filter by
  `OrganizationId` explicitly.
- **Envelope law** — agents emit one line of PascalCase JSON on stdout; **exit code 0 even for
  handled failures**; tracebacks to stderr only.
- **Agents are pure functions** — stdin `{"Draft":…,"Input":…}` → envelope. They never touch the DB.
- **Patches are the only mutation path** for a draft.
- **`SessionSchemaVersion` may only ever increase.**
- **Derived values are computed, never generated.** `doc.formatter` and `doc.carry_forward` are
  LLM-free.
- **Hebrew/RTL is the happy path.** Every string boundary is UTF-8; stdin is BOM-less on the C# side
  and BOM-tolerant (`utf-8-sig`) on the Python side.
- **`System.Activities`** in `Lus.Application.csproj` is Windows-only and unused — must stay
  conditional on `Windows_NT` or Linux/Docker builds break.
- **Cookie `Secure`** is `false` for localhost/dev, `true` in prod; `Domain` empty in dev,
  `.shiftiz.com` in prod.
