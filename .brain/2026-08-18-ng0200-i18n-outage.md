# NG0200 circular DI — the "i18n is broken" outage (2026-08-18)

> Symptom reported: the login page rendered raw keys — `common.appName`, `auth.login.subtitle`,
> `auth.login.email`, `auth.login.password`.
> Actual fault: **every `HttpClient` call in the app was dead.** i18n was just the visible part.

## The law (frozen)

**An HTTP interceptor must NEVER take an `HttpClient`-dependent service as a constructor
parameter.** Resolve it lazily from the `Injector` inside the interceptor instead.

Building `HttpClient` requires resolving `HTTP_INTERCEPTORS`. Any interceptor whose constructor
transitively needs `HttpClient` closes the loop and Angular throws
`NG0200: Circular dependency in DI detected for InjectionToken HTTP_INTERCEPTORS`.

Pinned by `src/app/Adapters/Interceptors/interceptor-di.spec.ts`.

(ArmyLuz states the same rule for its loading tier: *"`LoadingService` never injects anything
HTTP-adjacent (circular-DI law)"* — `docs/NON_BLOCKING_LOADING.md`. Lus violated it three times.)

## The three cycles

```
HttpClient -> HTTP_INTERCEPTORS -> CsrfInterceptor      -> CsrfService      -> HttpClient
                                -> HttpErrorInterceptor -> AuthService      -> HttpClient
                                -> HttpErrorInterceptor -> TranslateService -> TranslateHttpLoader -> HttpClient
```

The third is the cruel one: `TranslateService`'s loader **is** `TranslateHttpLoader`, so the very
service that renders translations pulled `HttpClient` into the interceptor constructor.

## Why it looked like an i18n bug

When `HttpClient` fails to construct, everything routed through it dies silently — no exception
reaches app code, requests simply never happen. What stayed working were assets fetched outside
`HttpClient` (`<img src>`), which is why SVG icons and the logo rendered fine while translations
did not.

## Diagnosis path (what actually settled it)

Guessing was cheap and wrong; browser evidence was decisive:

| Check | Result | Conclusion |
|---|---|---|
| keys present in `he.json`/`en.json` | ✅ correct values | not missing content |
| `curl localhost:4200/assets/i18n/he.json` | **200**, correct JSON | not a 404, not an asset-pipeline problem |
| `TranslateModule.forRoot` + `HttpLoaderFactory` | correctly wired | not configuration |
| `LanguagesType` enum values | lowercase `he`/`en` | not a filename-case problem |
| URL-rewriting interceptor | already skips `.json` | not URL rewriting |
| **browser network log** | **ZERO requests for `he.json`** | the fetch never happens |
| **browser console** | **NG0200 × repeated** | root cause |

The decisive moment was the network log: not a failed request — **no request at all**.

## The fix

`CsrfInterceptor` and `HttpErrorInterceptor` now hold an `Injector` and resolve the offending
services through a lazy getter:

```ts
private authServiceRef?: AuthService;
constructor(private router: Router, private notify: NotificationService, private injector: Injector) { }
private get authService(): AuthService {
  return (this.authServiceRef ??= this.injector.get(AuthService));
}
```

`Router` and `NotificationService` (MatSnackBar) have no HTTP dependency and stay eager.
